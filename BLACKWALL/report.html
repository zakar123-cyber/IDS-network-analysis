Rapport Méthodologique

Ce document justifie les choix architecturaux et les métriques de performance du prototype BLACK WALL, répondant directement aux exigences du Projet de Fin d'Année (Système de détection d'intrusions pédagogique).

1. Justification des Choix Techniques

Pourquoi Wazuh (HIDS/SIEM) ?

Bien que des solutions comme Snort ou Suricata soient excellentes pour l'analyse purement réseau (NIDS), le cahier des charges exigeait l'analyse de journaux et une restitution orientée supervision. Wazuh offre un agent léger permettant la centralisation immédiate d'événements OS et réseaux, ainsi qu'un moteur pré-configuré mappé au framework MITRE ATT&CK.

Pourquoi le Random Forest Classifier ?

Le projet demandait une approche hybride (règles + modèle). Le choix du Random Forest (implémentation scikit-learn) par rapport à un Réseau de Neurones Profonds (DNN) est justifié par le besoin "pédagogique". Le Random Forest est un modèle "Glass Box" (interprétable) : il est possible d'extraire l'importance de chaque variable (Feature Importance), permettant d'expliquer à un jury de manière déterministe pourquoi l'IA a classé un événement comme suspect.

Pourquoi l'architecture Frontend-First isolée ?

Le tableau de bord (Dashboard) a été bâti de manière à centraliser tous les flux de données (simulées via scripts, ou réelles via API) dans une interface web statiquement hébergeable. L'utilisation libre de dépendances CDN (Tailwind, Chart.js) permet d'avoir un prototype déployable et fonctionnel sur n'importe quel conteneur (NGINX/Apache) sans lourdeur de compilation Node.js pour la démonstration.

2. Jeu de Données et Simulation

La viabilité d'un IDS se juge à sa capacité à isoler le bruit des véritables attaques. Pour le prototype, les logs ingérés sont régis par un générateur stochastique modélisant deux types de comportements (décrits dans le manifeste des Scénarios) :

Trafic de Fond (Baseline)

Représente 85% de la masse de logs générés. Issus de connexions SSH autorisées et de journaux systèmes nominaux (Level 2 à 4).

Injections Hors-Normes (Attaques)

Représente 15% des logs. Des salves massives saturant la vélocité normale pour déclencher les règles Layer 1 (Level > 7) et marquer l'IA.

4. Limites du Projet

En accord avec le scope pédagogique, les limites suivantes doivent être retenues lors de l'évaluation :

  • Le Dashboard n'opère pas d'actions actives sur un pare-feu (Mode IDS strict). Les labels "BLOCKED" sont démontratifs des recommandations du produit.
  • Le générateur de données (JS/JSON) utilisé pour cette présentation UI ne capture pas les paquets PCAP sur l'interface hôte.
  • L'agent Wazuh a été sélectionné pour simplifier le parsing, ce qui crée une adhérence technologique forte à l'écosystème d'OSSEC.
  • Les Faux Positifs, bien qu'estimés faibles, demanderaient une curation manuelle en production constante via des listes d'exclusion (whitelists).
