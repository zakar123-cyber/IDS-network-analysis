System Architecture

Containerized.
Isolated.
Reproducible.

BLACK WALL runs as a fully isolated multi-container Docker stack. On the day of your demo, a single docker compose up starts the entire system — API, frontend, database, and Wazuh log mount — in front of any jury.

Notice de soutenance : Les données ingérées dans cet environnement sont issues de jeux de tests documentés et simulées dynamiquement. L'objectif est de démontrer la viabilité de la chaîne de détection (règles + ML), non pas de traiter un réseau en production réelle.

Wazuh Agent (Ubuntu Host)

Sends real-time JSON alerts via a mounted volume ./wazuh_logs to the backend container.

FastAPI Backend

Processes logs through static rules + ML engine. Exposes /analyze endpoint with structured JSON responses.

PostgreSQL Database

Stores alert history, risk scores and remediation status. Backend waits via depends_on health check.

React / Streamlit Frontend

SOC dashboard on port 80/8501. Polls the backend API and renders live charts and threat cards.

Limites du Prototype

Conformément aux exigences pédagogiques, ce SIEM est un prototype défensif démonstratif. Les limitations fonctionnelles suivantes ont été actées lors de la conception :

01

Données Simulées non Connectées (Air-Gapped)

Le tableau de bord n'écoute pas d'authentiques interfaces réseaux en temps réel. Le trafic, les attaques et le score ML sont générés aléatoirement via des scripts JS recréant des patterns d'attaques réalistes pour illustrer le paradigme de détection.

02

Passif vs Actif (IDS vs IPS)

Malgré la présence d'étiquettes "BLOCKED" ou "DROPPED" dans l'UI, le système fait du Monitoring passif (IDS). Il ne configure pas dynamiquement les règles `iptables` ou du pare-feu matériel de l'hôte test.

03

Modèle ML pré-entrainé & statique

L'algorithme Random Forest (RF-v2) utilisé pour noter le risque n'apprend pas en temps réel (Pas d'apprentissage continu non supervisé). Les poids catégoriels sont basés sur un jeu de données figé.
