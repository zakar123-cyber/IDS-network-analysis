Logique de Détection

Cette page expose la double couche de sécurité du SIEM BLACK WALL. Elle documente le pipeline d'analyse, l'approche prédictive de l'IA, les limites inhérentes (faux positifs) et inclut le dictionnaire complet des règles de détection Wazuh sous-jacentes.

Le Pipeline de Détection (Double Couche)

Afin d'éviter de se fier uniquement à des signatures rigides, le trafic est d'abord filtré par Wazuh (Layer 1) puis soumis à un modèle de Machine Learning Random Forest (Layer 2) pour consolider la décision.

1. Ingestion — Endpoint / Network Log

Un agent (ex: Ubuntu-VM) ou un capteur réseau génère un événement brut (fichier syslog, auth.log, apache access.log). Cet événement est envoyé au manager central.

2. Layer 1 — Moteur de Règles Wazuh

Signature

Le log est analysé contre le dictionnaire de règles. Si une signature ou un seuil est franchi (ex: 5 échecs SSH successifs), une alerte initiale est générée avec un niveau de criticité (ex: Level 10).

Exemple: Rule 5503 (SSH Brute Force) déclenchée. Criticité: 10/15.

3. Extraction des Caractéristiques (Features)

L'alerte brute est transformée en vecteur mathématique pour l'IA. Les données qualitatives sont converties en métriques quantitatives identifiables par les arbres de décision.

Heure: 03:00 (Nuit) Freq: 120 evt/sec Fail ratio: 98%

4. Layer 2 — Modèle Random Forest v2

Comportemental

Le modèle ML analyse les features extraites et les compare à sa baseline d'entraînement "Normal vs Suspect". Il génère un Score de Risque de 0 à 100 et attribue une probabilité (Confidence). Le bruit habituel est isolé des attaques ciblées.

5. Alerte Finale & Remédiation

Si Wazuh (Niveau > 7) ET le ML (Score > 70) concordent, l'analyste reçoit l'alerte sur le Dashboard. Une recommandation de mitigation est proposée et une action passive est loggée (simulant un blocage IP / WAF).

Limites & Faux Positifs

Aucun système n'est infaillible. Le paramétrage actuel produit volontairement quelques faux positifs lors de processus IT légitimes, démontrant les limites des règles statiques.

Scanner de Vulnérabilité (ex: Nessus)

Le SIEM alerte sur un Port Scan (Rule 100002) lors d'un audit interne mensuel planifié.

Solution métier : Créer une whitelist pour l'IP du serveur de scan dans la surcouche de règle Wazuh.

Scripts de Backup & Monitoring

Un serveur de supervision effectue des pings de santé très agressifs sur l'infrastructure (100 req/sec). Résultat : Fausse alerte ICMP Flood (Rule 100001).

Correction IA : Le modèle ML baisse fortement le score de risque s'il note que la fréquence réseau est parfaitement consistante dans le temps (un humain/bot aléatoire est plus erratique).

Oubli de Mot de Passe Massif

Un utilisateur légitime tente 5 fois de suite son mot de passe un lundi matin après ses congés. Wazuh déclenche une alerte Rule 5501.

Correction IA : L'IA classe ceci en risque FAIBLE car l'incident survient à une heure de bureau habituelle (08h00-09h00).

Random Forest v2 — L'Extracteur

Le modèle ML de la couche 2 ne lit pas la signature en texte brut (le "payload"). Il se concentre exclusivement sur une analyse comportementale en vectorisant le méta-contexte de la requête.

Horaire (Time Profile Feature)

Le poids décisionnel de cette feature est très élevé.
100 tentatives de connexion à 10h00 sont très différentes comportementalement de 100 tentatives de connexion à 03h00 du matin sur un serveur d'entreprise.

Vélocité (Events per second / minute)

Le modèle détecte qu'aucun humain normal ne peut envoyer une requête POST sur `/api/login` à la fréquence mécanique de 50 fois par seconde continuellement (Outil d'automatisation Hydra / Custom Script).

Diversité Réseau (Geo-clustering)

Un comportement suspect provenant d'une IP isolée est gérable. Le même comportement provenant simultanément de dizaines d'IPs différentes déclenchera dramatiquement le score de risque (DDoS, Botnet distribué).
